Roadmap: from three drawn architectures to three measured ones

The milestones that make the comparison of the Claude skills plugin, the LangGraph pipeline and a local MCP server real: one shared rubric, both pipelines scoring the same way, a working MCP server, and results committed to the repo. The source of truth is docs/roadmap.md; update both together.

Principles that hold at every milestone

Business rules live onceRubric, tracker rules and routing policy belong to core. A new approach is a new front end, never a rewrite.
Same inputs, same testsEvery approach runs against the same synthetic persona, job descriptions and gold scores.
Measure, don't assertClaims about token use, accuracy or reliability come with eval results in the repo.
Each stands aloneThe plugin never depends on the pipeline or the server being installed or running.

What depends on what

The milestones

1

Foundations

All tracks · done
  • Plugin released at 0.4.x, with evals for intake, Tier 2, resumes, profile and cleanup
  • core plus the evaluate graph, CLI, demo and unit tests on fakes
  • ADR 0001 (orchestration) and ADR 0002 (system of record)
2

One rubric

Shared core · done

Both approaches turn an evidence table into a score with the same code.

  • core/rubric.py, an exact copy of score.py, with a typed EvidenceTable
  • A test that fails if the copies differ
  • ADR 0003: how the rubric is shared
Done when

The same table scores identically in both, enforced by CI, with no behaviour change.

3

B scores like A

LangGraph · done

The model fills in evidence; the rubric computes the score.

  • assess_fit (model) and score (rubric) nodes
  • Structured outputs instead of forced tool_choice
  • The profile as an input; tracker Score Tier names
  • Prompt fit-scoring/2.0 and the first committed baseline
Done when

At least 75% of job-fit eval cases pass on the live model, and the baseline is committed.

4

Local MCP server

MCP · parallel · proposed
  • 4a: a probe server that logs what the client sends: does it start plugin servers, does it send Roots?
  • 4b: a job-search-local plugin; stdio server; Roots with a JOB_SEARCH_FOLDER fallback; profile, resume and style as resources; find_files, get_jd
  • 4c: gap_summary(since) computed in code, a weekly-review prompt, a skill, an eval case, ADR 0004
Done when

"What am I most often missing?" is answered from the server's counts, and its eval passes.

5

Measured comparison

Shared evals · done

The comparison page's claims become numbers.

  • The plugin's three gold Tier 2 cases through A and B, both on claude-sonnet-5-5, 3 runs each
  • Every run of both matched the gold score, requirements and evidence calls
  • Per job: A's whole run about 436,000 tokens in 12 calls and 79 s; B's scoring call about 4,000 tokens in 1 call and 5 s
Next

Three deliberately borderline gold cases, where judgment is more likely to differ.

6

B to parity

LangGraph · next
  • An intake graph: Gmail, parsers, canonical-URL dedup in core, Tier 1 score
  • A Tier 2 graph that starts from the Run Tier 2 checkbox
  • A SheetsTracker adapter; shadow-mode writes to their own tab; ADR 0002 updated
  • Local scheduling, and the known fixes in next_id and studio.py
Done when

B runs in shadow mode for a week next to A, with an agreement report.

7

Packaging for readers

Docs · first pass can start, final after 6
  • README: problem → this architecture → a short demo of each approach → results → ADRs → what's next
  • A written case study comparing the three
Done when

A cold reader gets from the problem to the evidence in two minutes.
